1. Generator provider: "prisma-client" NOT "prisma-client-js"
2. Generator output: "../src/generated/prisma" (mandatory in Prisma 7)
3. Generator moduleFormat: "cjs" (required for NestJS CommonJS compatibility)
4. datasource db: NO url field in schema.prisma — url goes in prisma.config.ts only
5. PrismaClient import: from '../../generated/prisma/client' NOT from '@prisma/client'
6. PrismaClient instantiation: ALWAYS super({ adapter }) — bare super() throws at startup
7. Seed config: in prisma.config.ts migrations.seed — NOT in package.json prisma field
8. prisma.config.ts imports: import { defineConfig, env } from "prisma/config"

- Import PrismaPg from '@prisma/adapter-pg'
- Import PrismaClient from '../../generated/prisma/client'

| Boundary | Description |
|----------|-------------|
| process.env.DATABASE_URL → PrismaClient | Credential injected at runtime; must not be logged or exposed in error messages |
| Generated Prisma client → schema.prisma | Generated code must match schema — drift causes silent type mismatches |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | DATABASE_URL in PrismaService | accept | Dev-only; NestJS does not log env vars by default; no explicit DATABASE_URL logging in PrismaService code |
