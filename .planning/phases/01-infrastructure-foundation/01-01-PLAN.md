<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem → Docker container | Bind mount exposes host source code; Windows filesystem events don't propagate to Linux inotify |
| .env file → docker-compose.yml | Credential injection via ${VAR} expansion — .env must never be committed |
| Developer machine → postgres:5432 | PostgreSQL port exposed to host for dev tooling (Prisma Studio, psql) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | .env credentials | mitigate | .env added to .gitignore; .env.example has placeholder values only — real credentials never committed |
| T-01-02 | Information Disclosure | DATABASE_URL in docker-compose env | accept | Dev-only setup; DATABASE_URL is passed as env var to containers, not logged by application code; acceptable in local dev context |
| T-01-03 | Elevation of Privilege | postgres:5432 exposed to host | accept | Development-only; port 5432 should be removed from docker-compose.yml before any staging/production deployment; documented in README |
| T-01-04 | Spoofing | Seed dev account passwords | accept | Seed accounts (Seller123!, Buyer123!) are development-only credentials documented in .env.example; not reused in production |
| T-01-SC | Tampering | npm packages in Dockerfile.dev | mitigate | All packages pre-audited in RESEARCH.md Package Legitimacy Audit — all Approved; no [ASSUMED] or [SUS] packages present |
</threat_model>
